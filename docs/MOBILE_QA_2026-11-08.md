# Mobile QA — 8 November 2026

Target: <https://tiffinperiod.insforge.site/>. Local repairs were verified against a production build served by Vite Preview. This report records the QA audit before publication; the subsequent release uses the repository's existing deploy-on-push workflow.

## Result

All 17 deployed games were opened and started with real browser touch events in Bangla and English on three emulated phone profiles: **102 game/profile/language flows and 711 completed control checks**. There were no captured JavaScript errors or HTTP error responses in those flows. The original browser suite covered complete matches and game-specific controls; its nine initial failures were rechecked after correcting stale test assumptions or reducing contention, and every non-skipped case passed across the original run and focused replays.

Four product defects were reproduced on the deployment tested during the audit and repaired locally. Physical phone compatibility and sustained frame rate have not been certified.

## Settings, records and offline use

Language, sound state, all five settings switches, volume and both player names persist after reload. The records regression checks stored score display. The service worker was allowed to activate, a navigation was cached, the browser was disconnected, and the hub was reloaded offline. All **17 game setup screens** then loaded offline. This passed against both the live site and the repaired local build. Native installation and a home-screen launch were not simulated.

## Performance and remaining limits

Cold-homepage first-contentful-paint samples were 0.576 s on compact, 4.688 s with CPU/network throttling, and 2.304 s on the large profile. These are diagnostic samples collected during a concurrent QA run, not repeatable device benchmarks. The lower-end profile's cold load deserves measurement on a physical phone. No trustworthy physical-device FPS, thermal, memory-pressure or battery claim can be made from these runs.

Still needed before claiming broad device certification:

- Physical low-end Android and current Android testing, including sustained 3D play.
- iPhone/iPad Safari and real safe-area/browser-toolbar behavior.
- Real simultaneous multi-finger gameplay and physical rotation/fullscreen behavior.
- Listening to sound and speech, especially Bangla voices, and checking vibration.
- Native PWA installation, launch from the home screen and recovery after OS suspension.
- Longer real-player online matches, rematches, reconnection and unstable mobile networks across all online games.

The audit does not enumerate every possible setting combination, game seed, tournament path or gesture sequence. No evidence supports promising that every possible click or device is fault-free.

## Durable learnings

### Release canary follow-up

The initial release's 13 focused mobile checks passed on the live site. An additional real-touch Dots and Boxes probe at 360 × 800 found that a tap following horizontal/vertical drags could receive pointer-up without a compatibility click. The existing mouse-driven drag test did not cover that sequence. The enhanced regression reproduced the failure against the live candidate. Touch/pen taps now play on pointer-up, with the existing click suppression preventing a duplicate move; mouse clicks retain their normal path. The regression includes short wiggles, both drag directions and a subsequent tap, using actual touch input on the mobile profile.

Evidence is retained in `.gstack/qa-reports/dots-touch-live-before/` and `.gstack/qa-reports/dots-touch-fixed/`. This is an additional issue found during release verification, separate from the four defects in the original audit.

### Operational notes

- Mobile Chromium can expand `innerWidth` to fit overflow and scale the page down. Compare geometry to the requested viewport, not only `innerWidth`.
- Wide games pause behind an orientation gate, so gameplay tests must rotate or explicitly choose upright play.
- In-game help requires both pause and resume callbacks. Verify that closing help also removes the underlying paused state.
- Use a raw `local` transport fixture. Use separate browser contexts without that fixture to prove real backend connectivity.
